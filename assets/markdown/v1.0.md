## Major New Features

<table width="100%">
  <tr>
    <td width="25%"><b>Custom Session Termination</b></td>
    <td>Configure flexible stopping criteria to heavily optimize training efficiency. This ensures you save valuable compute resources and prevent overfitting by automatically halting training the moment a model reaches convergence or a desired accuracy plateau.</td>
  </tr>

  <tr>
    <td><b>Multi-Framework Support</b></td>
    <td>Flotilla is now fully framework-agnostic. Train and aggregate federated models using <b>PyTorch</b>, <b>TensorFlow/Keras</b>, <b>JAX</b>, <b>Scikit-Learn</b>, or <b>ONNX Runtime</b>. The pluggable ML framework adapter layer lets you select the right tool for each model — simply set the <code>backend</code> field in your model's <code>config.yaml</code>. All built-in aggregation and training strategies work across every supported framework.</td>
  </tr>

  <tr>
    <td><b>Session Lifecycle Modules</b></td>
    <td>Define custom session orchestration flows via pluggable lifecycle modules. Built-in lifecycles include the standard round-based loop, Odin, and SurgeFL. Add your own under <code>src/server/lifecycle/</code>.</td>
  </tr>

  <tr>
    <td><b>Model Access & History</b></td>
    <td>Easily download global models and analyze results from any past FL session. This provides complete visibility and reproducibility, allowing researchers to instantly evaluate past experiments and seamlessly transition trained models directly into production.</td>
  </tr>

## Getting Started

### New Users
If you are brand new to Flotilla, head over to our **[Quick Setup Guide](quick_setup.md)** to install the framework and run your first federated learning session from scratch.

### Upgrading Existing Deployments
To seamlessly upgrade your existing projects to `v1.0`, follow these steps:

1. **Pull the latest changes:**
   ```bash
   git pull origin main
   ```
2. **Update your dependencies:**
   ```bash
   pip install -r requirements.txt
   ```
3. **Install optional framework dependencies** (only needed if your models use non-PyTorch frameworks):
   ```bash
   pip install tensorflow    # for TensorFlow/Keras models
   pip install jax jaxlib    # for JAX models
   pip install scikit-learn  # for Scikit-Learn models
   pip install onnxruntime   # for ONNX models
   ```
